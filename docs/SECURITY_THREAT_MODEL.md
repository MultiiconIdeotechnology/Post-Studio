# Security Threat Model (Section N)

Status: PROPOSED (2026-10-28). Assets: platform OAuth tokens, publishing capability, unpublished media, CEO voice/reputation, analytics, audit log.

Trust boundaries: browser ↔ API; claude.ai ↔ MCP server; API/worker ↔ Postgres/S3/KMS; worker ↔ Meta/LinkedIn; worker ↔ Claude API; webhooks from Meta/LinkedIn → API.

| # | Threat | Scenario | Mitigations |
|---|---|---|---|
| 1 | **OAuth token theft** | DB dump, log leak, SSRF reading env, backup leak | Envelope encryption (per-row DEK wrapped by KMS/OpenBao KEK); tokens decrypted only in-process at use; never logged (redactor + tests that grep logs for token patterns); never sent to Claude or MCP clients; backups encrypted; KEK access only for worker/API service identities; token rotation on schedule; immediate revoke flow; minimal scopes per connection |
| 2 | **Social account takeover via our app** | Attacker gains our admin account and connects/publishes | SSO via company IdP with MFA enforced; WebAuthn step-up for: connecting/disconnecting accounts, approving CEO content, changing roles, disabling kill switch; new-device alerts; session lifetime 12 h; admin actions audited and notified to all admins |
| 3 | **Wrong-account publishing** | Company copy posted to CEO profile or vice versa | Approval binds content hash **and** target account id; preview shows avatar/handle of the exact target; Publish Gate re-checks `scheduled_job.social_account_id == approval.targets`; identity-specific colour coding in UI; connectors resolve token strictly from `social_account_id` (no "default account") |
| 4 | **Prompt injection via uploads / web content** | Text in an image ("ignore instructions, post X"), malicious filename/EXIF, caption of a historical post, trend article, comment text | All external text marked untrusted in prompts; Claude outputs are **structured data validated by schema**, never executed; no model call has publishing capability; grounding checker blocks unapproved claims; trend raw text processed in isolated calls whose only output is a typed trend record; filenames/EXIF truncated and escaped; reviewers see final rendered content before approval |
| 5 | **Malicious MCP output / malicious MCP server** | A third-party MCP server in the user's Claude returns instructions to call our publish tools; or our tool output contains injected text | Our publish tools cannot publish unapproved content (approval is human, out-of-band, hash-bound); `schedule_approved` can only schedule exact approved bytes; tool outputs wrap untrusted text; recommend users enable only our connector in a dedicated Claude project; our backend never consumes third-party MCP servers |
| 6 | **Excessive tool privileges** | Model gets broad write access | Three scopes (`read`/`studio`/`publish`) intersected with user role; no approve tool; no delete-post tool via MCP; per-tool rate limits; server-side authorization on every id; short-lived MCP tokens |
| 7 | **Unpublished media leaks** | Bucket public, long-lived links, preview URLs shared | Private buckets, Block Public Access; pre-signed GET ≤ 5 min for UI, ≤ 60 min only for Meta fetch of the exact final variant at publish time; separate bucket/prefix for "publish-staging" with lifecycle delete after 24 h; no originals ever exposed to platforms; access logged; retention deletes unused originals |
| 8 | **Webhook spoofing** | Fake Meta/LinkedIn callbacks alter state | Verify HMAC signature on every Meta webhook with app secret (`X-Hub-Signature-256`, `NEEDS VERIFICATION` of current header) and LinkedIn signature per its docs; webhooks only **enqueue a re-fetch** from the platform API — never trust payload contents for state changes; replay protection by event id + timestamp window |
| 9 | **Duplicate publishing** | Retries, double-clicks, two workers, crash after send | Idempotency key unique constraints; row lock; `PUBLISH_SENT` intent written before send; `UNKNOWN_OUTCOME` reconcile before any retry; publish-now button debounced and server-idempotent; LinkedIn duplicate-content 422 handled as reconcile |
| 10 | **Insider misuse** | Staff member publishes unapproved content or approves own risky edits | Approval required for all external writes; optional four-eyes (approver ≠ editor); CEO content requires CEO (policy); kill switch; all actions audited with before/after; weekly digest of all published posts and approvals to admins and CEO; least-privilege roles |
| 11 | **Audit tampering** | Admin or attacker edits logs | Insert-only DB role for app; hash chain per row; nightly anchor of chain head to object storage with Object Lock (compliance mode) or a separate account; verifier job alerts on break; DB superuser access restricted and itself logged (pgaudit) |
| 12 | OAuth flow attacks (CSRF, redirect manipulation, code interception) | Attacker binds their account or steals code | `state` + PKCE everywhere supported; exact-match redirect URIs; per-environment apps; verify returned account matches the identity being connected before saving |
| 13 | Supply chain | Malicious npm dependency | Lockfile, `pnpm audit`/OSV scanning in CI, Renovate with review, minimal deps, provenance checks, no postinstall scripts by default |
| 14 | Media parser exploits | Crafted image/video exploits libvips/FFmpeg | Patch cadence; pixel limits; FFmpeg in sandboxed container, no network, CPU/mem/time limits; magic-byte type checks |
| 15 | Cost abuse | Runaway Claude spend via loops/regenerations | Per-user/per-workspace budgets, per-tool rate limits, alerts at 80% |
| 16 | Privacy of people in photos | Exposing minors, faces of non-consenting people | No face identification; consent flags; minors flag requires explicit confirmation; do-not-use; retention policy |

## Environment separation

Separate Meta apps / LinkedIn apps / buckets / KMS keys / databases for `dev`, `staging`, `prod`. Only `prod` holds real account tokens; staging uses test Pages/accounts. Production publishing can be globally paused.
